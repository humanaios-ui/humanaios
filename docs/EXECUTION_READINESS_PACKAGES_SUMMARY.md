## CRITICAL SUCCESS FACTORS

1. **κ ≥ 0.80 gate (Week 3 end):** If not achieved, delay Layer 1 main assessment; clarify scoring ambiguities
2. **Daily κ monitoring:** Identify low-agreement elements; address same day (don't let issues cascade)
3. **Stopping rules armed:** If CI-width > 0.30 or ρ < 0.50, halt and investigate (don't push through)

3. **Practice element solution key:** Must be defensible; coders will compare their scores to these
4. **Z2 governance gate:** If Z2 rejects codebook, codebook author must revise quickly (affects Phase 3b.2 start date)

## TROUBLESHOOTING: What to Do If...

### **"Windows κ is only 0.72 by Friday Sep 27 (below 0.80 gate)"**

**Actions:**
1. Identify 3–5 lowest-agreement elements (κ < 0.65)
2. Codebook author clarifies scoring guidance for these elements (focused Q&A session)
3. Coders re-score these elements only (not full 21 re-do)
4. Re-measure κ; target κ ≥ 0.80 within 2–3 days
5. If still below, escalate to Carly: may need to adjust scoring framework or clarify boundaries

---

### **"K8s codebook author is behind (only 40 pages by end of Week 1, target 80)"**

**Actions:**
1. Identify blocker: Is it research/learning time? Writing speed? Unclear requirements?
2. If learning: Confirm operationalization template is clear; provide writing support
3. If unclear requirements: Escalate to Carly; clarify scope (all 7 O-types needed? all 5 perspectives needed?)
4. Catch-up plan: Extend Week 1 work into Week 2 (front-load writing)
5. Z2 checkpoint: Communicate "Week 1 extended to cover research; Week 2–3 remain on track"

---

### **"Coder team or codebook author has scheduling conflicts during critical training/writing weeks"**

**Actions:**
1. Communicate immediately (don't wait for Friday checkpoint)
2. Escalate to Carly: Request resource adjustment (backfill with backup coder/author?)
3. Reschedule training/writing if needed; communicate new dates to Z2
4. Assess impact on gates: Will delays push back Windows Layer 1 completion? K8s codebook approval?

---

### **"Z2 governance rejects K8s codebook at final gate (2026-10-20)"**

**Actions:**
1. Determine specific issues: Operationalization gaps? Dimension clarity? Practice elements weak?
2. Codebook author has 1–2 days to revise (target: re-present on 2026-10-22)
3. If major revision needed: K8s Layer 1 coder training delayed (impacts Phase 3b.2 start)
4. Communicate delay to Carly; assess impact on parallel execution timeline
