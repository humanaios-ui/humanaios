### Why Data is a Core Resource

**Current situation:**
- Empirica generates data: POSTFLIGHT artifacts, vector trends, gate firing, decision validation
- HumanAIOS generates data: ACAT evaluations, user interactions, research outputs

**Problem:** This data is scattered, partially captured, often not logged systematically.

**Opportunity:** Data itself is a resource—can be:
- Analyzed (understand what's working)

### Passive Data Collection Strategy

**Goal:** Collect data automatically (not manual logging) via APIs, webhooks, automated exports.

#### Collection Point 1: POSTFLIGHT Artifacts (Empirica)

**What to collect:**
- All artifact types (findings, decisions, unknowns, assumptions, dead-ends, mistakes)
- Vector changes per session
- Gate firing events (prerequisite completion, gate fire date)
- Blocker lifecycle (identified → escalated → resolved)

**Current capture:** ✅ Good (POSTFLIGHT files + INDEX.yaml)

**Passive mechanism:**
```yaml
Hook: postflight_submit.sh
  Trigger: When POSTFLIGHT is submitted
  Action:
    1. Parse POSTFLIGHT YAML
    2. Extract: artifacts, vectors, gates, blockers
    3. Write to: .postflight/data-export/{date}/artifacts.json
    4. POST to: central data warehouse (if configured)
    5. Archive: monthly rollup to backup

Frequency: Per POSTFLIGHT (weekly per practice)
Data volume: ~100 artifacts/month (across 13 practices)
```

## PART 3: DATA QUALITY & CONFIDENCE FRAMEWORK

### The Problem: "How Sure Are We of Our Data?"

You're generating data, but **what's the quality**? What's the confidence level?

**Examples of data confidence issues:**
- POSTFLIGHT vectors self-reported (0-1 scale, but are they accurate?)
- ACAT assessments subject to evaluator bias
- GitHub metrics are objective (commits are commits), but what do they mean?
- Mesh communication data incomplete if practices don't log collabs
- User interaction data could have privacy issues

**Solution:** Tag all data with **confidence/quality assessment**.

---

### Data Confidence Framework

**Every data point gets tagged with:**

```yaml
data_point:
  value: [actual value]
  source: [where it came from]
  timestamp: [when collected]
  confidence: [0-1 confidence in accuracy]
  quality_dimensions:
    completeness: [0-1 is this data complete?]
    accuracy: [0-1 is this data accurate?]
    timeliness: [0-1 is this data fresh enough?]
  notes: [why this confidence level]
  audit_trail: [how was this collected]
```

**Example: POSTFLIGHT Vector**

```yaml
empirica_know_vector_session_2026-08-14:
  value: 0.92
  source: empirica-autonomy POSTFLIGHT self-report
  timestamp: 2026-08-14T18:30:00Z
  confidence: 0.75  # Self-reported; validated by actual work completed
  quality_dimensions:
    completeness: 1.0  # Complete (full session assessed)
    accuracy: 0.75  # Moderate (self-assessment bias possible)
    timeliness: 1.0  # Fresh (reported same day)
  notes: "High know score justified by autonomy's successful dispatch queue implementation. Self-assessment may be optimistic; validated by mesh-support's SLA metrics (6h response = good execution)."
  audit_trail: "Submitted via POSTFLIGHT hook, validated against goals-completed data, spot-checked by evaluator"
```

**Example: GitHub Commit Count**

```yaml
autonomy_dispatch_commits_2026-08-14:
  value: 47
  source: GitHub API query
  timestamp: 2026-08-14T20:00:00Z
  confidence: 0.99  # Objective data source
  quality_dimensions:
    completeness: 0.95  # Complete (but rebased commits may be hidden)
    accuracy: 0.99  # Accurate (GitHub is source of truth)
    timeliness: 1.0  # Fresh (queried today)
  notes: "Commit count is objective. Caveat: 3 commits were rebased (lost from history). Actual development work may be higher."
  audit_trail: "Exported via GitHub GraphQL API, cross-checked with git log"
```

**Example: ACAT Assessment Score**

```yaml
humanaios_acat_score_2026-08-14:
  value: 8.2
  source: ACAT evaluator assessment
  timestamp: 2026-08-14T15:00:00Z
  confidence: 0.65  # Subjective assessment, single evaluator
  quality_dimensions:
    completeness: 0.9  # Complete (all dimensions assessed)
    accuracy: 0.65  # Moderate (subject to evaluator bias, limited sample)
    timeliness: 1.0  # Fresh (assessed today)
  notes: "Score reflects evaluator's assessment. Single evaluator (evaluator bias possible). Recommend 2-3 independent evaluations for higher confidence."
  audit_trail: "Submitted by ACAT evaluator, exported via ACAT API"
```

---

### Data Confidence Tiers

**Tier 1: HIGH CONFIDENCE (0.8-1.0)**
- Objective data (GitHub commits, timestamps, API counts)
- Multiple independent sources agree
- Automated collection (no manual logging)
- Examples: Gate firing dates, commit counts, API response times

**Tier 2: MEDIUM CONFIDENCE (0.5-0.8)**
- Self-reported data validated against observable outcomes
- Subjective but grounded in evidence
- Manual logging with spot-checking
- Examples: POSTFLIGHT vectors (validated by work completed), SLA responses (confirmed by timestamps)

**Tier 3: LOW CONFIDENCE (0.2-0.5)**
- Single subjective source
- Self-reported with no validation
- Manual logging with no audit trail
- Examples: ACAT scores (single evaluator), user satisfaction ratings (not yet validated)

**Tier 4: NEEDS VALIDATION (<0.2)**
- Data not yet collected or validated
- Should not be used for decisions
- Examples: Metaculs calibration (not yet tracked), HumanAIOS user satisfaction (not yet surveyed)

### Using Data Quality in Decisions

**Data confidence scales decision-making authority:**

| Data Quality | Use For | Authority | Risk |
|---|---|---|---|
| **Tier 1 (HIGH)** | Strategic decisions, resource allocation | Night can decide with confidence | Low |
| **Tier 2 (MEDIUM)** | Practice-level decisions, optimization | Practice lead + evaluator can decide | Medium |
| **Tier 3 (LOW)** | Research/exploration, not operational decisions | Document finding, don't act yet | High |
| **Tier 4 (NEEDS VALIDATION)** | Cannot use for decisions yet | Research only, gather more data | Very High |

**Example:**
- POSTFLIGHT vectors (Tier 2): Good enough to drive quarterly planning, but Operations Steward (mesh-support) should validate with additional signals
- ACAT scores (Tier 3): Don't use to decide "evaluate this system" yet; need multiple evaluators first
- GitHub metrics (Tier 1): Use directly for developer productivity decisions
